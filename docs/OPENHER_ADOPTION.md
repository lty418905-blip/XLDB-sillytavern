学习不接受模型生成的权重。模型只提交经历评估候选，本地校验后计算奖励：事件施加前的总挫折减去施加后的总挫折，再限制到 `[-1,1]`。稳定关系保持有来源的缓慢更新，作为12维神经上下文中的关系深度、信任和情感基调，避免一次候选抹掉长期关系。尚无已实现的未来承诺分类输入时，`pendingForesight` 为0，不编造推测。

## 为本产品调整的边界

- 已接受且当前角色可知的每条来源驱动一次学习；未接受预览、普通召回与界面查看不训练。酒馆和 Agent 使用同一核心。
- 上游聊天代码先 forward、之后又调用 step，产生第二次 forward。本项目每个接受事件使用一次 forward→learn→tick，并对返回信号施加热噪声，避免 UI 读取次数改变学习轨迹。
- 所有随机量使用每个角色自己的 `xoshiro128** + Box–Muller` 状态，保存四个 PRNG 字、Gaussian 缓存等全部信息。它替代上游进程全局 random；同一数值 seed 不代表与 Python `random.Random` 输出相同。
- 持久保存权重、偏置、递归、驱力参数、最近隐层/输入、学习计数、总奖励、age、挫折相变、信号历史及 PRNG。历史最多100条；上游会暂增到200再截为100。
- 默认按稳定角色身份初始化随机基线；已有明确手工基线配置继续保留。分支继承原身份和学习状态，不因 branch ID 变化重新随机初始化。
- 现实时间只读投影在副本上前向计算并丢弃递归/随机推进；重复同一时刻读取不累积学习。需要持久变化的经历由接受事务提交。
- 新鲜模型输出与已保存历史分开校验。历史稀疏候选的兼容读取不代表新模型可以缺项；不因新合同重新调用模型解释旧事件。状态另记最后一次 Critic 观测时间，反复读取不刷新该时间。
- 旧情境在对应时钟经过12小时后，读时改用中性计算基线；它不表示已经观察到用户情绪转好，也不重置角色长期情感、稳定关系或权重。12小时是当前产品启发式，尚无质量实验支持它是最佳时长。
- 当前 `timeOfDay` 由事件／读取时钟及 IANA 时区计算为本地一天的比例（午夜0、中午0.5、临近次日午夜接近1）；剧情使用剧情时钟，未知剧情时间使用中性值0.5，模型不能指定当前时间。这是 XLDB 明确后的刻度，不宣称与上游“早晨到深夜”的模糊说明完全相同。
- 已配置剧情模式时，初始化、逐条经历和只读代谢均使用接受事件折叠出的剧情时钟；现实等待不推进NPC情绪时间，计划和回忆不推进当前时钟。伴侣模式继续使用现实时间。
- 旧确定性版本没有神经训练历史。升级从已保存的有效候选重建新版本神经轨迹，不再次询问模型改写既有事实，也不宣称恢复了从未运行的旧学习。原始记忆和业务状态仍以来源为权威。
- 不执行上游虚构情境预热：人工模拟奖励不能冒充角色真实经历。不采用其 UI、媒体、Style Memory 或 EverMemOS 服务；这不削减本次神经学习模块的范围。

## 参数与表达

Agent 伴侣增加等待回复的来源投影（`src/emotion/contact-affect.ts`）：确认送达且正文确实期待回应的消息，严格超过 12 小时后，结合提前说明和当前 OpenHer 状态产生思念、担忧、委屈的表达依据。它们是有来源的角色感受候选，不是上游现成的三类情绪分类器，也不是用户意图的事实。勿扰时段的思念破例不制造回复义务；不确定投递在补充确认后若仍无可靠发送时间，不据此计算精确等待时长。

等待期间在克隆的神经状态上以前瞻期待输入进行前向投影，不修改长期信任、权重、学习计数或随机状态。用户返场时，等待经历与本轮说明进入原有 accepted-source 情绪处理，随正常事件学习一次；返回本身结束未完成期待。模糊期限标明需要澄清，不伪造截止日期；返场解释不会被改写为早已告知，但应参与当前修复。编辑、删除及重放以当前有效来源重建这些材料，不能凭旧投递正文恢复已删除内容。当前验证层级见 `PROJECT_STATUS.md`，不以命名感受代替真实表达质量验收。

每角色可配置驱力基线、是否使用随机基线、代谢率、稳定关系变化率，以及 Hebbian 学习率（默认0.02）、相变阈值（默认2）、温度系数（默认0.12）和最低温度（默认0.03）。修改参数使对应旧派生结果失效，按来源重建；不能在旧权重上悄悄混用两套配置。

前台通过 `src/emotion/expression.ts` 的只读 `xldb-emotion-expression-v1` 投影接收当前驱力、挫折、八维信号的两端含义、稳定关系、观测时效及同层已接受事件趋势，不收到权重、随机状态或其它角色的学习材料。历史情景评价只从已经过访问与遗忘投影的清楚 MemoryView 取得，不解释成当前信号的唯一原因。等待体验只带结构和来源标识，不另带原话；称呼建议合并进同一个块。信号用于影响表达，不授予角色新知识，也不能改写客观账本。

上游实际上还通过刻度含义、趋势与风格样例引导正文。本项目现已按自身访问与生命周期语义实现刻度解释和同层趋势，未移植 Style Memory。普通生成、原生角色、Agent recall 和主动候选复用相同投影；未知或私有剧情时间不进入表达，读取不训练。Critic 历史输入另加观测时间与性质，不将旧状态作为本轮新证据。来源边界见 [源码核验](OPENHER_EXPRESSION_SOURCE_REVIEW.md)，实施路线见 [6 Pro 工程方案](OPENHER_6PRO_ENGINEERING_PLAN.md)。代码接线不等于已证明正文遵循程度提高，质量对照与长期体验分别验收。

## 验证边界

自动化覆盖独立公式预期、两层非零学习、负奖励相变、驱力满足与积累、热噪声、序列化后继续一致、输入不变和坏状态拒绝。存储验收还须覆盖真实 SQLite 的幂等、隔离、编辑/删除、重启、分支与备份恢复。

真实模型是否正确理解事件、学习后的表达是否可信、长期是否漂移，是单独质量层级。组件测试通过不等于完整情绪体验通过；实际结果及限制统一记录在 `PROJECT_STATUS.md`。
