# OpenHer 情緒與神經學習採用說明

上游固定於 `ef5b2145c9c15582499ecc5fb9d10376d82eccdf`, 原始碼不隨倉庫發佈, 需要時自上游倉庫取得該提交. 許可證為 Apache-2.0, 安裝包保留 `shared/third-party/OpenHer-LICENSE`. 產品以 TypeScript 執行, 不依賴 Python.

使用者已要求完整神經學習作為 NPC/伴侶情緒更新依據. 原先固定公式投影僅是歷史版本; 當前移植程式碼位於 `shared/src/emotion/neural.ts`, 事件與代謝接入位於 `shared/src/emotion/openher.ts`. 實現與實機驗收狀態分別見原始碼工作區 `PROJECT_STATUS.md`.

2026-09-20三輪諮詢後的路線決定: 保留本頁已採用機制; 另以衝突/修復, 不同時間與事件次數, 遞迴/噪聲/權重消融驗證情緒慣性, 再決定是否加入快慢情緒變數. 主要NPC啟用上限與角色卡/世界書初始化屬於後續宿主/狀態管理工作; 不改變獨立持久權重和來源學習原則.EverMemOS/EverOS僅進入事件歸併, 畫像與前瞻事項的有界複用評估, 尚未採用服務或新程式碼. 具體順序與採用門檻以 [工程路線](../../ENGINEERING_PLAN.md) 為準, 不把諮詢當成新的執行證據.

## 2026-09-29 保真度核驗: 當前程式碼與上游的差異

本節依 2026-09-29 的保真度審計和 `shared/tests/fixtures/openher-golden/deviations.json` 寫成, 陳述當前程式碼今天做什麼. 下文的"計劃"指設計中的切片(OH1-OH9)與使用者裁定 21-24a, 只是路線: OH1(K1, R1)已完成, 其餘切片仍是計劃. 神經核心(`neuralForward`, `neuralLearn`, `neuralStep`, `neuralThermodynamic` 與代謝公式)由 OH0 一致性測試(`shared/tests/openher-conformance.test.mjs`)逐步鎖定為上游 `ef5b214`; 夾具另含 `reads.json`, 由 `generate_golden.py --reads` 生成, 共 75 個讀取點, 對照上游 `time_metabolism` + `sync_to_agent`, 容差 1e-12, 測試時不執行 Python. 下列差異都發生在核心之外的編排, 輸入和讀取層, 而這些層決定了核心實際收到什麼.

- **關係輸入恆為 0 (K4)**: 場景, 酒館和伴侶路徑在 `shared/src/core/models.ts:344` 與 `shared/src/scene/service.ts:1193, 1217` 清空 `stableRelationDelta`, 12維神經上下文中的關係深度, 信任和情感基調在這些路徑恆為 0; 只有舊核心路徑(`shared/src/core/store.ts:298`)會餵入. 計劃於 OH3 改為上游式 EMA, 以 XLDB 的關係先驗為先驗.
- **種子含聊天 ID (K6)**: 情緒身份種子為 `xldb-emotion-v2` 加世界, 會話(酒館中即 chatId), 角色和 NPC(`shared/src/core/store.ts:342`, `shared/src/scene/types.ts:153`), 所以同一張角色卡在每個新聊天都得到另一副基因組, 並非"穩定角色身份". 計劃於 OH2 改為卡片身份加 NPC 正名的卡片級基因組(裁定 22, 22a), 既有聊天保留原基因組.

## 為本產品調整的邊界

- 已接受且當前角色可知的每條來源驅動一次學習; 未接受預覽, 普通召回與介面檢視不訓練. 酒館和 Agent 使用同一核心.
- 上游聊天程式碼先 forward, 之後又呼叫 step, 產生第二次 forward. 本專案每個接受事件使用一次 forward→learn→tick, 並對返回訊號施加熱噪聲, 避免 UI 讀取次數改變學習軌跡. 但這只保證讀取不改變學習. OH1 之後, 最近一次已接受事件起 12 小時內, `emotionAt` 回傳該事件凍結的信號, 不前向也不重抽噪聲(見上節 R1); 重新前向並重抽噪聲只發生在滿 12 小時後(以 `STALE_CONTEXT` 在可丟棄的複本上計算), 或走伴侶接觸投影路徑(`behavioralSignalsAt`, 每次呼叫前向並重抽噪聲, 推遲到 0.3.0 OH8a).
- 所有隨機量使用每個角色自己的 `xoshiro128** + Box-Muller` 狀態, 儲存四個 PRNG 字,Gaussian 快取等全部資訊. 它替代上游程序全域 random; 同一數值 seed 不代表與 Python `random.Random` 輸出相同.
- 持久儲存權重, 偏置, 遞迴, 驅力參數, 最近隱層/輸入, 學習計數, 總獎勵,age, 挫折相變, 訊號歷史及 PRNG. 歷史最多100條; 上游會暫增到200再截為100.
- 預設按情緒身份種子初始化隨機基線, 該種子含世界, 會話(酒館中即 chatId), 角色和 NPC, 所以同一張角色卡在每個新聊天得到另一副基因組, 這與"穩定角色身份"不同, 見上節; 已有明確手工基線設定繼續保留. 分支繼承原身份和學習狀態, 不因 branch ID 變化重新隨機初始化.
- 現即時間只讀投影在副本上前向計算並丟棄遞迴/隨機推進; 重複同一時刻讀取不累積學習. 需要持久變化的經歷由接受事務提交.
- 新鮮模型輸出與已儲存歷史分開校驗. 歷史稀疏候選的相容讀取不代表新模型可以缺項; 不因新合同重新呼叫模型解釋舊事件. 狀態另記最後一次 Critic 觀測時間, 反覆讀取不重新整理該時間.
- 舊情境在對應時鐘經過12小時後, 讀時改用中性計算基線(`STALE_CONTEXT`; 未滿12小時的讀取凍結為最近已接受事件的信號, 不前向, 見上節 R1); 它不表示已經觀察到使用者情緒轉好, 也不重置角色長期情感, 穩定關係或權重.12小時是當前產品啟發式, 尚無質量實驗支援它是最佳時長.
- 當前 `timeOfDay` 由事件/讀取時鐘及 IANA 時區計算為本地一天的比例(午夜0, 中午0.5, 臨近次日午夜接近1); 劇情使用劇情時鐘, 模型不能指定當前時間. 只讀投影在時間未知時使用中性值0.5; 但未設定劇情時鐘的酒館角色扮演, 學習事件取聊天建立時刻的凍結時間, 並非 0.5. 這個刻度與上游相反: 上游明確定義 0=早晨, 1=深夜(`genome_engine.py:70`), 本移植午夜為 0, 使深夜被映成低值且在午夜跳變; 它不是"對模糊說明的明確化", 而是偏差, 計劃於 OH3 改回上游語義, 見上節.
- 已設定劇情模式時, 初始化, 逐條經歷和只讀代謝均使用接受事件摺疊出的劇情時鐘; 現實等待不推進NPC情緒時間, 計劃和回憶不推進當前時鐘. 伴侶模式繼續使用現即時間.
- 舊確定性版本沒有神經訓練歷史. 升級從已儲存的有效候選重建新版本神經軌跡, 不再次詢問模型改寫既有事實, 也不宣稱恢復了從未執行的舊學習. 原始記憶和業務狀態仍以來源為權威.
- 不執行上游虛構情境預熱: 人工模擬獎勵不能冒充角色真實經歷. 不採用其 UI, 媒體,Style Memory 或 EverMemOS 服務; 這不削減本次神經學習模組的範圍. 另有未移植的上游功能: 驅力基線彈性演化, 結晶門檻, 內心念頭/最終回覆/表達方式三段演員格式, 每角色 `signal_overrides` 與英文錨點, 見上節.

## 參數與表達

Agent 伴侶增加等待回覆的來源投影(`shared/src/emotion/contact-affect.ts`): 確認送達且正文確實期待回應的訊息, 嚴格超過 12 小時後, 結合提前說明和當前 OpenHer 狀態產生思念, 擔憂, 委屈的表達依據. 它們是有來源的角色感受候選, 不是上游現成的三類情緒分類器, 也不是使用者意圖的事實. 勿擾時段的思念破例不製造回覆義務; 不確定投遞在補充確認後若仍無可靠傳送時間, 不據此計算精確等待時長.

等待期間在克隆的神經狀態上以前瞻期待輸入進行前向投影, 不修改長期信任, 權重, 學習計數或隨機狀態. 使用者返場時, 等待經歷與本輪說明進入原有 accepted-source 情緒處理, 隨正常事件學習一次; 返回本身結束未完成期待. 模糊期限標明需要澄清, 不偽造截止日期; 返場解釋不會被改寫為早已告知, 但應參與當前修復. 編輯, 刪除及重放以當前有效來源重建這些材料, 不能憑舊投遞正文恢復已刪除內容. 當前驗證層級見 `PROJECT_STATUS.md`, 不以命名感受代替真實表達質量驗收.

每角色可設定驅力基線, 是否使用隨機基線, 代謝率, 穩定關係變化率, 以及 Hebbian 學習率(預設0.02), 相變閾值(預設2), 溫度係數(預設0.12)和最低溫度(預設0.03). 修改參數使對應舊派生結果失效, 按來源重建; 不能在舊權重上悄悄混用兩套設定.

前臺通過 `shared/src/emotion/expression.ts` 的只讀 `xldb-emotion-expression-v1` 投影接收當前驅力, 挫折, 八維訊號的兩端含義, 穩定關係, 觀測時效及同層已接受事件趨勢, 不收到權重, 隨機狀態或其它角色的學習材料. 歷史情景評價只從已經過訪問與遺忘投影的清楚 MemoryView 取得, 不解釋成當前訊號的唯一原因. 等待體驗只帶結構和來源標識, 不另帶原話; 稱呼建議合併進同一個塊. 訊號用於影響表達, 不授予角色新知識, 也不能改寫客觀賬本.

上游實際上還通過刻度含義, 趨勢與風格樣例引導正文. 本專案現已按自身訪問與生命週期語義實現刻度解釋和同層趨勢, 未移植 Style Memory. 普通生成, 原生角色,Agent recall 和主動候選複用相同投影; 未知或私有劇情時間不進入表達, 讀取不訓練.Critic 歷史輸入另加觀測時間與性質, 但前一次 `criticContext` 仍逐字傳給評論器, 實測常被原樣抄回, 舊狀態實際上會被當成本輪證據, 見上節. 來源邊界見 [原始碼核驗](OPENHER_EXPRESSION_SOURCE_REVIEW.md), 實施路線見 [6 Pro 工程方案](OPENHER_6PRO_ENGINEERING_PLAN.md). 程式碼接線不等於已證明正文遵循程度提高, 質量對照與長期體驗分別驗收.

## 驗證邊界

自動化覆蓋獨立公式預期(神經核心另由 OH0 一致性測試鎖定為上游), 兩層非零學習, 負獎勵相變, 驅力滿足與積累(只證明本移植公式; 上游聊天中每輪被覆寫而無效), 熱噪聲, 序列化後繼續一致, 輸入不變和壞狀態拒絕. 儲存驗收還須覆蓋真實 SQLite 的冪等, 隔離, 編輯/刪除, 重啟, 分支與備份恢復.

真實模型是否正確理解事件, 學習後的表達是否可信, 長期是否漂移, 是單獨質量層級. 元件測試通過不等於完整情緒體驗通過; 實際結果及限制統一記錄在 `PROJECT_STATUS.md`.
